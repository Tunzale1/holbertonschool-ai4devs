# Prompt Use Cases

## Code Quality

- **Refactoring**
  - **Goal**: Improve code readability, structure, and performance.
  - **Input**: Existing source code in [LANGUAGE].
  - **Output**: Refactored and optimized code with an explanation of improvements.

- **Style Enforcement**
  - **Goal**: Ensure consistent coding standards and formatting.
  - **Input**: Code block with inconsistent naming and formatting.
  - **Output**: Rewritten code following standard style guidelines.

- **Code Review**
  - **Goal**: Identify inefficient or problematic coding practices.
  - **Input**: Source code in [LANGUAGE].
  - **Output**: Code review with suggestions for improvement.

## Debugging

- **Error Detection**
  - **Goal**: Identify errors and explain why they occur.
  - **Input**: Code containing errors and error messages.
  - **Output**: List of identified errors with explanations and corrections.

- **Bug Fixing**
  - **Goal**: Find and fix bugs in existing code.
  - **Input**: Code with unexpected behavior.
  - **Output**: Corrected code with an explanation of the solution.

- **Performance Debugging**
  - **Goal**: Identify performance bottlenecks and improve execution speed.
  - **Input**: Slow-running code and relevant performance details.
  - **Output**: Optimized code and recommendations for better performance.

## Documentation

- **Code Comments**
  - **Goal**: Make code easier to understand and maintain.
  - **Input**: Source code in [LANGUAGE].
  - **Output**: Code with clear and meaningful comments.

- **Function Documentation**
  - **Goal**: Explain the purpose, parameters, and return values of functions.
  - **Input**: Function or class implementation.
  - **Output**: Structured documentation with descriptions and examples.

- **README Generation**
  - **Goal**: Create clear project documentation for developers.
  - **Input**: Project description, features, and installation instructions.
  - **Output**: A complete README file with setup and usage instructions.

## Testing

- **Unit Test Generation**
  - **Goal**: Verify that individual functions work correctly.
  - **Input**: Source function and expected behavior.
  - **Output**: Unit tests covering normal and edge cases.

- **Test Case Creation**
  - **Goal**: Identify different scenarios to test an application.
  - **Input**: Feature description and requirements.
  - **Output**: A list of positive, negative, and boundary test cases.

- **Bug Regression Testing**
  - **Goal**: Ensure previously fixed bugs do not appear again.
  - **Input**: Bug description and updated source code.
  - **Output**: Regression tests that verify the bug remains fixed.
